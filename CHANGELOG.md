# Changelog

## 0.3.0-beta (unreleased)

Everything since 0.2.2-beta.

### Added

- **Close only the terminals of a space.** While a space has terminal tabs, its `...` menu in the space list ends with *Close terminals*: it closes all of them and leaves the space as it is, open or not. While one of them is still running it asks first and says how many; tabs that have all ended are closed without a question.
- **The dot of a node blinks while its terminal is at work.** While the output of a logged-in session goes on (a program that is running, the echo of what you type), the green dot of the node its tab was opened from blinks twice a second; it dims instead of going out, and it stands still again about a second after the output stops. Only that node blinks, not the jump hosts of the path, and only once logged in (a yellow or red dot never blinks). It blinks also while its tab is not in front or the panel is minimized. Apart from the ring that turns while a save runs, it is the only thing in the app that moves by itself.
- **Quit in the tray asks while terminals are running.** A window closed to the tray (*Settings > Close to tray*) keeps its terminals running: still logged in, and what runs in them goes on (a tmux there stays attached). *Quit* in the tray menu ends them all, so it now says how many are running and quits only on *Quit*; *Cancel* is the default. Without a running terminal it quits at once, as before.
- **The keys of the terminal are listed in the app.** *Show Info* in the gear menu now has a short list: copy and paste, find (Ctrl+Shift+F), text size (Ctrl with +, - and 0), Enter to connect again in an ended tab, the middle click that closes a tab. They were told only in the README. The icon there is smaller, so the window still fits without scrolling.
- **The window opens where it was.** Its size, its place and whether it was maximized are remembered. A window that would open where no screen is any more (a monitor that was unplugged) or that is larger than its screen starts at the default size or is fitted to the screen. On a screen scaled to 125 %, 150 % or 175 % the place and the size are moved to the nearest values that are whole pixels there (by 3 px at most), so the window is the same every time it opens; without that it grew by a few pixels with every start.
- **Find in the terminal.** Ctrl+Shift+F opens a small search field over the terminal of the selected tab; it looks through everything that has scrolled by (up to 5000 lines). The newest match is selected while typing, Enter goes to the one before, Shift+Enter to the next, Esc closes and leaves the match selected (Ctrl+C copies it). Upper and lower case are the same unless the small *Aa* button of the field is on; pressing it searches again from the newest output. Text selected in the terminal (inside one line) is taken as the text to find. Selecting another tab closes the field. Ctrl+F alone still reaches the remote program.
- **Font size of the terminals.** Ctrl with + (or =) makes the text bigger, Ctrl with - smaller and Ctrl+0 puts it back to 13 px, also with the keys of the number pad. The size is one for all terminals, goes from 8 to 32 px and is remembered with the other settings. Ctrl+Shift+- still reaches the remote program (undo in emacs and nano).
- **The space shows where the selected terminal tab comes from.** The node a tab was opened from is marked (pink frame, sun-colored shadow) while that tab is in front; selecting another tab moves the mark to its node. Through ProxyJump it is the last node of the path. Nothing is marked while the panel is minimized.
- **Maximize the terminal panel.** The button with the arrow up at the right end of the tab row raises the panel to just under the header, so the terminals take the place of the canvas. The same button brings the canvas back with the panel at the height it had; the space buttons in the header (eye, lock, reset view, arrange) are away meanwhile, because they have nothing to act on. Dragging works too: the top edge stops where the canvas keeps its 200px, and about 80px further up the panel snaps to the full height; dragging the edge down again lets go, before or after releasing. Each space remembers whether its panel is maximized, a minimized panel comes back maximized, and closing the last tab ends it, so the next terminal opens under the canvas.
- **The space scales with the canvas.** When the canvas gets higher or lower (the terminal panel opens, closes or is dragged, the window is resized), the space grows and shrinks with it like the scenery behind it, and what was in the middle stays in the middle. It follows the height of the canvas: closing the panel brings back exactly the ratio the panel had taken, also when you changed the zoom while the panel was open, and a change of the width alone leaves the size as it is. The view is saved together with the size of the canvas it was chosen in, so a space also opens in the same proportion in a window of another height. The starting view (a space that was never moved, or after *Reset view*) is the one view that does not follow the window: it is the same in a window of every height, and only the terminal panel reduces it.
- **A middle click closes a terminal tab**, like the x at its right end.
- **Split the terminal panel left and right.** A new button at the right end of the tab row shows two terminals side by side: the selected tab left, the tab next to it right. Each half has its own row of tabs over it: the split moves that one tab into the right row, and a tab dragged from one row into the other moves to that half and comes into sight there. The tab in sight in the other half has a frame in the color of the selected one. Click into a half (or on one of its tabs) to type there; a tab shows in the half of its row, and a new terminal opens in the row of the half that has the keyboard. Closing a tab in sight shows the next tab of the same row. The button again, or closing or dragging away the last tab of a half, ends the split, and the tabs are one row again in their order of before. It needs two tabs, the halves are equally wide, and each space remembers its split.
- **Terminal tabs with the same name are numbered.** Two or more tabs of one space with the same name show a number after it, `web (1)`, `web (2)`, in the order they were opened. The number stays whole when the name is cut off in a narrow tab, and the tooltip and the close button use it too. A name that is there once has no number.
- **Reorder terminal tabs.** Drag a tab by its name to move it; the other tabs make room while you drag. The close button still only closes.
- **Hide node details.** The eye button left of the lock masks user, host, port and forwards under every node with `***` (each part of an address on its own, `***.***.***.***`, so the lines stay where they are and nothing can be read or counted) and keeps only the names (the address also leaves the tooltips); a second click shows them again. It is remembered like the other settings.
- **Reset view and arrange nodes.** *Reset view*, the button left of the lock (which keeps its place right next to the gear menu), brings the canvas back to its starting zoom and position, also while the editor is locked. While the editor is unlocked, *Arrange nodes* shows next to it and lines all nodes up in the middle of the visible canvas: each path runs left to right on its own row in link order, nodes behind the same jump host stack in the next column, and the view zooms out when the group does not fit. The text under a node is part of the space it takes. Like dragging, the new positions are saved when you lock the editor. With the terminal panel open both are made for the canvas without the panel and shown reduced like every view: the starting view is exactly the starting view again when the panel closes, and arranged nodes keep to the middle part of the canvas, so they still fit then. After the window was resized, *Reset view* on a space that already shows the starting view changes nothing.
- **A hint on an empty space.** A new or emptied item showed only the scenery, and nothing said that servers are added with a right-click. It now says so in the middle of the canvas (or to unlock the editor first while it is locked); the hint goes away with the first node and lets right-clicks through.
- **Connection state on the canvas.** A path opened in the app terminal is yellow while connecting, turns pink with a green dot once ssh has logged in, and becomes a red dashed line with a red dot when the connection failed (until its tab is closed or reconnected). ssh reports the login itself through an invisible marker (`LocalCommand`), so a session waiting for a password stays "connecting". The terminal tab's dot and tooltip follow the same states.
- **Reconnect a failed terminal tab.** A session you end yourself (`exit` after logging in, Ctrl+C while connecting or on a forwarding tab) closes its tab right away. Tabs are as wide as their name, with the close button at the right end. A tab whose connection failed or broke stays, and Enter in its terminal reconnects: the same connection starts again in the same tab (the path lights up again). There is no reconnect button on the tab. The request with its password stays in the main process until the tab is closed; the window never keeps it.
- **Terminals inside the app.** Connect, ProxyJump and forwards open in a panel at the bottom of the window (xterm.js + node-pty), one tab per session, instead of a separate Git Bash window. Key passphrases and other prompts are typed into the tab; closing a tab ends the session. *Settings > Open SSH in* brings back the Git Bash window.
- **Background effects.** *Settings > Background* tones down the scenery behind the canvas so the nodes stand out: **Depth** (default: blurred, faded, a light haze on the horizon, so the nodes float in front), **CRT** (scan lines and dark corners), **Soft** (faded, dark edges), **Vivid** (the full scene; lines get a dark outline so they stay visible over the bright sun and grid) or **Off**. Only the scenery changes; nodes, lines and text stay sharp. *Settings > Node glass* (0 to 20 px, off by default) puts the text under each node (name, address, forwards) on a light frosted glass panel, as wide as the text, that blurs the scenery behind it, with any background.
- **Terminal colors.** *Settings > Terminal colors* sets how strong the colors of programs are in the terminal of the app: **Vivid** (the neon colors of the palette as they are), **Soft** (the default: the same hues, a little less bright and less colorful) or **Muted** (calmer still). The neon colors are made for dots and lines; a program that paints a whole line with one, like the green status line of tmux, was glaring. In Soft and Muted bold text uses a slightly stronger shade of the same color, and black is the background color of the palette. Saving the setting changes the open terminals at once. The canvas and the rest of the app keep their colors.
- **Copy and paste in the terminal.** Like in Windows Terminal: select text and press Ctrl+C (or Ctrl+Shift+C, Ctrl+Insert) to copy; Ctrl+V (or Ctrl+Shift+V, Shift+Insert) pastes. A right click copies the selection, or pastes when nothing is selected. Ctrl+C with nothing selected still interrupts the remote program. The cursor does not blink, so it stays calm while a program redraws a progress line.
- **Open paths show on the canvas.** While a terminal in the app is open, the connections along its path are thicker and pink, with the arrow in a second color, and the nodes on it show a small green dot (like the dot on the terminal tab). The states are told apart by their colors, standing still. Nodes are matched by user, host and port, so the same path in another item shows it too. (Not for the separate Git Bash window, whose sessions the app cannot see.)
- **Port forwarding on a node.** A node carries its own forwards (`local port -> target host : target port`). The tunnel goes through the node and every previous node, each with its own authentication. The target host defaults to `localhost`. The node shows a counter on its start button and a summary line of the enabled forwards.
- **Password authentication** as an alternative to a key, for Connect, ProxyJump and forwarding. Passwords are stored as plain text; exporting an item that contains one asks for confirmation.
- **A different authentication per hop.** Key, password, key + password, or neither can be mixed in one path. `keyboard-interactive` password prompts are answered as well; key passphrases and one-time codes are asked in the terminal.
- **Copy SSH config** copies a node (previous nodes as `ProxyJump`, forwards as `LocalForward`, `Exec` as `RemoteCommand`) in `~/.ssh/config` format.
- **From SSH config.** The canvas menu of an unlocked space has a second item, *From SSH config*: paste `Host` blocks of an SSH config and each becomes a node that holds only what is written there (`HostName`, `User`, `Port`, `IdentityFile`, `RemoteCommand`, `LocalForward`). The rest stays empty; only the port is filled in with 22 when the text names none, as ssh would use. A `ProxyJump` to another host of the text becomes a connection, so what *Copy SSH config* wrote comes back as the same path. The dialog lists what will be made, and what is not used or left out (other keywords, `Host *`, `Match`, a jump host that is not in the text), before anything is created. When the text would go too far, the first press of *Create* makes nothing and lists the reasons: more than 10 nodes at once, hosts left out over the limit of 50, values ssh would refuse, nodes the space already has (same user, host and port); *Create anyway* makes them, *Back* goes back to the text.
- Port inputs show only invalid values; enabled forwards with missing ports are flagged.
- **The canvas position and zoom are remembered** for each item and restored when it is opened again, also after restarting the app.
- **Icon picker.** The node image is chosen from a grid of all icons instead of stepping through them one by one. It works with the keyboard too (arrow keys, Home, End).
- Unit tests, tests that run the generated scripts under bash, and CI on Ubuntu and Windows.

### Changed

- **A terminal tab is named like its node, without the count of jump hosts.** A session through previous nodes had `(+1)` after the name, which ran into the number of tabs with the same name (`app (+1) (2)`). The tooltip of the tab says it now ("through 1 previous node"), and the space shows the path anyway.
- **The app says "space" everywhere.** The list said *item* (*New item*, *Import Items...*, *No items yet*), the messages *projects* (*Failed to save projects*), and the gear menu had *Export Space*. The list and its menu, the header, the hints on the canvas and the messages now all say *space*: *New space*, *Remove spaces*, *Import spaces...*, *Export spaces...*, *No spaces yet*, *No space open*, *Failed to save spaces*. *Export Space* exports every space and is *Export All Spaces* now, so that it is not taken for *Export spaces...* of the list, which exports the selected ones. The data file keeps its name, `projects.json`.
- **A minimized terminal panel stays at the bottom.** The dash at the right end of the tab row used to take the whole panel away and put a terminal button with a count into the header. Now the tab row stays where it is, at the bottom of the window, without the terminals above it. A click on a tab shows that terminal again, and the dash has become an arrow up that shows the panel as it was. The header has no terminal button any more. No tab is marked as selected while the panel is minimized, and no node on the canvas.

- **Enter saves the settings.** In *Settings*, Enter in the *Git Bash path* field does what the Save button does. The Enter that only finishes a character while typing Korean, Japanese or Chinese does not.

- **Node Setting shows only what is filled in while the editor is locked.** Empty fields and the icon grid are left out, since nothing can be changed there; a node without any value says so. Unlock the editor to see and edit every field.
- **A node under the pointer changes color instead of moving, and a clicked node gets no look.** Hovering a node used to lift it by two pixels with a larger shadow; now its frame takes the palette's sun color and its background gets lighter, and it stays where it is. Clicking a node while editing no longer gives it a pink frame: there was nothing one could do with a selected node. The pink frame now only marks the node of the terminal tab in front.
- **Saving shows in the header.** While the spaces are being written to disk, a small, faint ring turns left of the header buttons (the buttons keep their places). Most saves take a moment only; it stays visible when the disk is slow or the file is held by another program.
- **Nothing is animated.** The buttons over a node and the popovers show at once instead of fading in, and so does everything new in this version: nothing on the canvas or behind it moves or blinks by itself, and the terminal tabs do not slide while one is dragged. The one thing that moves is the ring in the header while a save runs.
- **In a locked space a drag on a node moves the canvas.** A locked node cannot be moved or selected, but it still took the mouse: a drag that started on its picture, name, details or sockets did nothing, so in a full space there was little room left to grab the canvas. Such a drag now moves the canvas as on the background. Under the pointer a locked node keeps its look: its frame and background stay as they are, and the pointer is the arrow of the canvas instead of the hand. Its name and details still show their tooltips, so a detail that is cut off can be read whole. The buttons above a node (connect, forwards, settings) work as before and still appear with the mouse over the node. Nothing changes while the editor is unlocked.
- **The terminal panel's arrow is now a minimize button.** The down arrow at the right end of the tab row looked like "lower" but hid the whole panel. It is a dash now, like a window's minimize button, next to the new maximize button; it still hides the panel while the sessions keep running, and the terminal button in the header still shows it again.
- **Pretendard for regular text.** Body text, menus, labels and descriptions are set in Pretendard (bundled, SIL Open Font License); until now they fell back to the system font, because Bootstrap overrode the app's own choice. The pixel font of titles and name tags and the monospace font of addresses and terminals are unchanged.
- **The sidebar is gone; the title opens the space list.** Wherever a side menu sat, it covered the canvas or the terminals. The name of the open space in the header is now a button: the list (search, `+`, rename, reorder, import and export, as before) opens under it and closes when you pick a space, press Escape or click outside. It is open when the app starts, and the hamburger button is removed. The search box, `+` and the `...` menu share one row.
- **Terminals belong to their space.** The panel shows only the tabs opened from the space that is open; opening another space puts them out of sight while the sessions keep running, and coming back brings them back with the same tab in front (and the panel hidden if you had hidden it). The space list shows a small terminal mark with the number of tabs next to each name. Paths on the canvas light up only for the open space's own sessions (before, the same server in another item lit up too). Removing a space closes its terminals.
- **Double-click resets the view.** A double-click on the canvas no longer zooms in; it does what *Reset view* does and goes back to the starting zoom and position. In a locked space a double-click on a node counts as the canvas (not on its buttons); while editing, double-clicks on nodes leave the view alone, and double-clicks on lines always do.
- **Nodes are connected with two clicks.** Click the start socket, then the target socket. Dragging from a socket and releasing on another one left the line hanging without connecting on Windows; a release now keeps the line following the mouse until you click the target (or empty canvas to cancel).
- **Build and dependencies.** Vue CLI 4 / webpack 4 is replaced by electron-vite / Vite 7 (the old toolchain no longer installed with a current npm). Electron 16 -> 44, electron-builder 26, electron-store 11, ESLint 9. Vue stays on 2.7 and Rete on v1. Sources moved to `src/main`, `src/preload` and `src/renderer`.
- **ssh is no longer started from a shell string.** Values are validated in the main process, written into a temporary script and passed to Git Bash. The renderer is sandboxed and only gets a small IPC API.
- **Spaces live in `projects.json`** in the app data folder (atomic write, `.bak` backup) instead of the browser storage. Older data is migrated on first launch.
- The Forward and ProxyJump buttons no longer need a key on the previous node. They are available when every previous node has user, host and port.
- A key given for a hop is the only key offered to it (`IdentitiesOnly`). A busy local port now makes a forward fail visibly.
- The canvas can be panned without a limit (it was stuck inside 1024x1024). Deleting a node that has content asks first.
- **A flat synthwave look** with high contrast: a dark violet night with a neon perspective grid, a striped sun clipped at the horizon and a pixel skyline behind the canvas, all in solid colors without glow or blur. Nodes are square dark panels with a neon border and a hard black shadow (pink with a yellow shadow when selected), the name on a pink tag in a pixel font, user / host / port in a monospace font on a dark plate so they stay readable over the scenery, square sockets and a cyan connection with a pink arrow. The header, the terminal panel and every dialog carry a three-color band; buttons, menus, tabs and labels use pixel capitals, and switches and the terminal tab buttons are square as well. *Settings > Theme* offers three palettes (Neon Night, Sunset Drive, Vapor Blue); the terminal follows the palette. Fonts: VT323 and JetBrains Mono (both OFL), bundled with the app.
- **Visual polish.** A dot grid instead of the checkerboard behind the canvas; on a node the name is bold and user / host / port are lighter and smaller; a node without an image shows a neutral server symbol instead of an empty grey frame; popovers and the Settings and Info dialogs are white rounded cards with the same shadow as the right click menu; the open item in the sidebar has a highlight and a blue frame only for keyboard focus; thinner scrollbars; smaller labels in the node settings. Second pass: lighter nodes (2px dark border, soft shadow that grows on hover, a blue ring instead of a dark cover when selected), thinner grey connections, the node menu as round white buttons, the name of the opened item in the header, a pill shaped search box, and confirmation dialogs and toasts as rounded cards.
- The lock button's tooltip no longer stays on screen (showing the opposite label) after a click; it uses the same plain tooltip as the other header buttons. *Close to system tray* in Settings is now *Close to tray* with a short explanation.
- Popovers opened with the keyboard take the focus, so Tab continues inside them. Popovers are opaque and close with Escape. The right click menus are redesigned: white card with rounded corners, icons, a red *Delete*, a short fade-in, and the canvas entry reads *Add node*.
- Accessibility: the icon-only controls (node menu, sidebar, header, forwards) are real buttons with names for screen readers and tooltips, keyboard focus is visible and reveals the node menu, and the grey helper texts are darker.

### Fixed

- **`[<35;...M` could show up as typed text in a terminal on Windows.** While a program on the server asks the terminal for every move of the mouse, each move over the terminal sends it a short report. Right after the terminal changed its size, Git's ssh sometimes lost the first character of such a report (3 and 4 of 10 in two runs; the ssh that comes with Windows lost none), and the program took the rest for typed text. On Windows the app no longer sends the moves of the mouse while no button is pressed; clicks, drags with a button down and the wheel reach the program as before. The price: what a program does only when the mouse moves without a button (a highlight under the pointer) does not happen in the app on Windows. A click or a turn of the wheel right after a size change can still lose that character: it is the same problem of Git's ssh as the size changes it does not pass on (*Known problem on Windows* in the README).
- **A host with a `%` could not be reached through ProxyJump or a forward, and a copied config with one was refused.** ssh reads `%` in `HostName` and `RemoteCommand` of a config as the start of a token (`%h`, `%u`, ...), so the zone of a link-local IPv6 address (`fe80::1%eth0`) ended such a session at once with "unknown key %e", and *Copy SSH config* gave a config ssh refused for it and for an exec like `date +%Y`. A `%` is written as `%%` there now (as in `IdentityFile` already), and *From SSH config* reads it back as one.
- **Connect failed at once with a key file whose path has a `%`.** ssh looks for the file given with `-i` under its name and then reads its `%` as the start of a token, so such a path ended the session before it connected ("unknown key %e"), and written as `%%` the file was not found. Such a path is handed over as an `IdentityFile` option now, with the `%` doubled; any other path still goes with `-i`, which says so in the terminal when the file is missing.
- **An exec command that ended in `;` or `&`, or had a comment, opened no shell.** The command and the shell after it were joined with `; `, which made `cd /srv;` and `tail -f log &` a syntax error (the session ended at once) and turned `exec $SHELL` into part of a comment after `htop # monitor` (the session ended with the command). They are joined with a new line now. In *Copy SSH config* a `;` at the end is dropped, and a command that ends in `&` is left out like one of several lines, since `RemoteCommand` is a single line.
- **A data file saved with a byte order mark could not be read.** Windows PowerShell 5.1 and Notepad's "UTF-8 with BOM" put one at the start of a file. Such an export was refused as "not valid JSON", such a `projects.json` (edited by hand) kept the app from opening the spaces, and such a `config.json` was read as empty: the settings and the place of the window went back to the defaults without a word, and the next change wrote over the file. All three are read as they are now.
- **An export or a `projects.json` saved in UTF-16 could not be read.** Windows PowerShell 5.1 writes UTF-16 with `>` and `Out-File` unless told otherwise, and Notepad does with "UTF-16 LE" or "UTF-16 BE". Such an export was refused as "not valid JSON", and such a `projects.json` kept the app from opening the spaces. Both are read by their byte order mark now. A `config.json` in UTF-16 is still read as empty, as the library that reads it takes it as UTF-8.
- **A folder as the Git Bash path gave an error that did not say where to fix it.** With the folder Git was installed in (instead of its `git-bash.exe`) under *Settings > Git Bash path*, a terminal showed only "File not found" and a Git Bash window "spawn ... ENOENT". Now both say that Git Bash was not found at that path and to check the setting, as for a path that does not exist.
- **A very long selection in a terminal was not copied, without a word.** The app put at most 1 MB on the clipboard (about a million characters), and a full scrollback of dense output (a long base64 text, a log) selected in a wide window is more than that: nothing was copied, and nothing said so. The limit is now 16 million characters, more than a terminal holds, and a selection over it would get a message instead.
- **A long paste into a terminal was dropped without a word.** Text of more than 64 KB (about 65 000 characters: a long log, a file as base64) pasted into a terminal was thrown away, and nothing said so: the app takes at most that much from its page at once. Such a paste is still not sent, but a message now says so and gives its length, so it can be pasted in parts (or a file copied with `scp`). The limit stays because of Git's ssh on Windows: it reads a paste at a few hundred characters a second and does nothing else meanwhile, so a long paste would hold the session for minutes (16 000 characters took 48 seconds to reach a server; of 150 000, nothing had arrived after seven minutes, and a server that checks whether its clients are alive had ended the connection). Ctrl+V and the right click no longer cut the clipboard at 1 MB, so the message gives the true length.
- **The app could crash when many terminals ended at the same moment (Windows).** A reload, a closed window and the end of the app end all terminals of the window at once, and the library that runs the terminals could crash then: the whole app was gone in an instant. It happened once with sixteen terminals in the real window; a test that ended 32 at once crashed in 4 of 40 rounds. The app now ends them one after another (about ten milliseconds each), and the same test did not crash again in 20 rounds.
- **When the page of the window died, its terminals ran on with no screen.** A reload or a closed window ends the terminals of that window, but a page that crashed (its renderer process ended, for example out of memory) left them running: ssh stayed logged in with nothing to show it (on the server, a tmux stayed attached) until the window was closed or the app ended. In the real window a crash with a ProxyJump session left both of its connections open. They are now ended as soon as the page is gone. The window itself still stays empty after such a crash: close it, or quit the app from the tray where closing only hides it.
- **The app did not start when its settings file could not be opened at all.** A damaged `config.json` is read as empty (see "A damaged settings file" below), but one that cannot be opened (a folder of that name, a file without permission or held by another program) still stopped the start with Electron's error box. Now the app starts with the default settings and says so in a message that stays: why the file could not be opened and in which folder. Settings changed meanwhile are kept until the app ends; the file is not touched.
- **A reload while terminals were being opened left their sessions running with no tab.** A terminal starts a moment after the click: the app first writes the small start-up script of the session. When the window was reloaded or closed in that moment, the session started all the same, after the terminals of that window had been ended, and ran on with no tab to show it: ssh connected and held its connection until the app ended. In the real window a reload right after twelve requests left ten of them running. Such a session is no longer started, and its files are removed. The same moment let more than 16 terminals run at once when many were asked for together (the app's own page asks for one per click, but twenty asked for at once all ran); the limit now counts the terminals that are still starting.
- **Main refuses what the page of the app never sends.** Three requests of the page did harm when they got something other than what the app sends; the app itself never did that, only a wrong call could (a mistake in a later version, for example). A save that got a list holding the text of an empty list (`["[]"]`) instead of the text itself read it as an empty list and wrote it over `projects.json` (the old content went to the backup). A fake mouse move (the page asks for one after a drag in the space list) to a place no screen has, such as 3e38, left the window without any mouse input. And a terminal asked for with a kind that cannot be turned into text was answered with an error of the call instead of a message. Each of them is now refused like any other wrong request. A mouse move to a place outside the window is still made, as before: it takes the hover away after a drag let go out there. Found by calling every request of the page with some 900 wrong values in the real window; nothing else misbehaved.
- **Closed terminals left their start-up files in the temp folder (Windows).** Every session of the terminal in the app writes a small script into the temp folder, and for ProxyJump and forwards an ssh config as well: no passwords, but the hosts, ports, user names and key paths of the path. The script removes them when it ends, but on Windows a closed tab, a reload, the end of the app and Ctrl+C while connecting end it before it gets that far, so the files stayed for a day or longer (the app only sweeps older ones when it starts). The app now removes them itself the moment a session ends.
- **A terminal tab closed at once could leave its session running.** A tab closed in the moment between the click on a node and the start of its session was gone from the panel, but the session started all the same and went on with no tab to show it: where ssh needs nothing typed it logged in and held its connection until the window was reloaded or the app was closed (on the server, a tmux started by that login stays attached). Such a session is now ended as soon as it has started.
- **A node with forwards the app cannot read was drawn empty, and the nodes behind it lost their path.** Only a file changed by hand holds such forwards: something that is no list, or a forward whose target host is no text. The node was drawn without its name and address, and with forwards that are no list the nodes after it connected directly, without their jump hosts, and nothing said so. Such a space is not opened any more, like other data the editor cannot read (further down): a message names the node, and the file stays as it is.
- **After some changes a node went on with the path it had before.** A click that puts a link into a left socket that already has one, and the removal of a node that has links, left the nodes behind with the nodes that had been before them: *Connect* went through the jump hosts of before, and the copied SSH config and the summary of the forwards said the same, until something else was changed or the space was locked. The paths are worked out after every change now.
- **Clicks on left sockets could take links away.** A click on a left socket without a link puts that socket in the hand, to be linked with a click on a right socket. With it in the hand, a click on another left socket removed the link of that socket and linked nothing, so a few clicks could empty a space of its links. Such a click does nothing now.
- **Two clicks could link nodes in a circle.** A node could be linked back to one before it, or to itself, and nothing said that this is a mistake: the paths of a space with a loop cannot be worked out, so every node of it connected directly, without its jump hosts. Such a link is not made any more, and a hint under the canvas says why; a link that was already in that socket stays where it was. A space that already has a loop opens as before, now with a message that names the nodes of the loop; its paths come back once one of those links is taken away.
- **A space with data the editor cannot read was opened all the same, and locking then saved what was on the canvas over it.** Only a file made or changed by hand holds such data: the data of another program, a node of a kind the app does not know or without a position, a link to a node that is not there, two links into one node. The canvas kept the nodes of the space opened before it under the new name, or showed a part of the space, and nothing said so; the next lock saved that as the space. Such a space is not opened any more: a message names it and says what is wrong with it, the space that was open stays as it is, and the data stays in the file as it was.
- **A space with a loop in its links lost the settings of all its nodes.** Two clicks are enough to link a node back to one before it. The paths of such a space cannot be worked out, and the nodes took their values only from that calculation: opened again, every node of the space was empty (*(untitled)*), and locking it then saved the nodes that way. Names, users, hosts, ports, keys, passwords and forwards were gone from the file. A node now reads its own values when it is drawn. Such a loop can no longer be drawn (the entry above); in a space that already has one, no node knows the nodes before it until one of those links is taken away.
- **Closing the window right after locking could lose the changes when the save was slow.** Locking saves the space, and unless the app is set to hide in the tray, closing the window ends it. The app ended without waiting for a save that was still being written. A save takes a few milliseconds, but while another program (a virus scanner, an indexer) has `projects.json` open for a moment, the app keeps trying for up to a second and a half, and a window closed in that time took the changes of the lock with it. The app now ends when the save has (it waits a few seconds at most).
- **A damaged `projects.json` was taken for "nothing saved" and written over.** When the file could not be read and there was no backup that could be (a power cut, a disk that was full, an edit by hand that went wrong), the app started with an empty list without a word, and the first space made after that replaced the file and its backup. The app now says which file is wrong and where it is, in a message that stays until it is closed, and saves nothing until the file is repaired or removed: what is left of the spaces stays on the disk. A file that is merely missing is still a first start, and a good backup still opens when only the file itself is damaged. A long folder path in an error message is wrapped instead of cut off at the side.
- **A damaged settings file no longer keeps the app from starting.** When `config.json` was empty or cut off (a power cut can leave it like that), the app showed an error box at every start until the file was deleted by hand. It now starts with the default settings and writes the file anew. The spaces are in another file and were never affected.
- **An error message no longer covers the buttons of the header.** A message such as *Failed to save spaces* opened at the very top of the window, over the lock and the gear, and stayed there for five seconds. It now opens just under the header.
- **Closing the window while the editor was unlocked lost the changes without a word.** Changes are saved when the editor is locked; opening another space asked first, but the close button, *Refresh Window* and *Quit* in the tray menu did not. They ask now (*Discard changes* or *Cancel*, Cancel is the default). Closing to the tray does not ask: nothing is lost there. Terminals also stay alive when a quit is cancelled.
- **Bold text in the terminal was drawn in two fonts.** The first bold letters of a session (the name in a colored prompt, for example) came out in another font, mixed with the right one, and stayed that way. The bold weight of the terminal font was only read when it was first needed, which was too late for the terminal; both weights are read when the app starts now.
- **Gaps in the lines that programs draw in the app terminal.** Rulers, frames and filled bars (Claude Code, tmux, progress bars) were drawn with the letters of the font, so at some display scales they broke between the rows or between the cells. The terminal now draws these characters itself, exactly as large as a cell (the WebGL renderer of xterm.js; it falls back to the old way of drawing when WebGL is not available).
- **Saving sometimes failed with "ENOENT: no such file or directory, rename ...projects.json.tmp".** The app saves from several places (locking the editor, changing the space list, moving the canvas), and two saves at the same moment used the same temporary file: the one that finished first took it away from the other, and the older of the two could even be the one that stayed. Saves now run one after the other, in the order they were asked for. And when Windows refuses to replace the file because another program has it open for a moment, the save tries again a few times instead of failing.
- **Full-screen programs in the app terminal on Windows 10 (tmux, vim, Claude Code, Codex).** The terminal went through the console layer (ConPTY) that is built into Windows, and the one in Windows 10 draws a program's output into a screen of its own and sends that on. The mouse and the alternate screen never reached the terminal, and whenever a program redrew part of the screen the cursor showed up in that part: against a test server, in 59 of 127 painted frames; now in none. The app now uses the newer ConPTY that comes with node-pty (from Windows Terminal), which hands everything on as it is; if that one cannot start, the terminal falls back to the one in Windows.
- On Windows, making the terminal panel taller (for example maximizing it) lost the lines that had just scrolled out of view: they came back into the terminal and were overwritten with blank lines. The terminal now knows it is talking to a Windows console and keeps them.
- **A screen that is being redrawn is shown in one piece.** The output of a program that redraws the screen (Claude Code, tmux, a progress line) reaches the app in dozens of small pieces, and the terminal could be painted in between: half a redraw, with the cursor where that piece ended. The pieces are now collected for 8 ms and shown together (against a test server one redraw arrives as one piece instead of about 25).
- **The terminal cursor has the text color**, with the character under it in the background color, as terminals do by default. It had the palette's main color, which made every cursor movement of a redrawing program stand out.
- **A right click in the terminal is left to a program that uses the mouse** (tmux with `mouse on`, vim, Claude Code). The click was sent to the program and pasted the clipboard into it as well. Hold Shift for the terminal's own copy and paste, as for selecting text in such a program.
- A node clicked while editing stayed selected after the editor was locked, where nothing can be selected or deselected; and because the node of the selected terminal tab has the same look, the leftover could pass for it. Locking the editor now clears the selection.
- **Shadows can be told apart from what casts them.** The hard shadows of nodes, name tags, menus, popovers and dialogs were black on a background that is almost black: the shadow could not be seen, and neither could the edge of a dark panel lying on it. Every palette now has its own shadow color, lighter than the background and the panels and darker than the borders.
- On Windows, Ctrl+C while a connection was still being made left the tab open with "exit status 512". It closes the tab now, as on Linux.
- Resizing the terminal in the moment its session ended could raise an error in the main process (the pty refuses to be resized once its program has ended). Such a resize is now dropped.
- In the space list the `...` menu of a space and the *More actions* menu were cut off at the bottom edge of the list when the list was short (for example right after adding the first space with `+`), so most of their entries could not be seen. The menus now open over the edge of the list.
- In a low window the terminal panel kept its height and squeezed the canvas down to a strip. The panel now gives way so the canvas keeps at least 200px (the panel itself never goes below 140px), and it returns to the height you chose when the window gets taller again.
- Opening the `...` menu of the space that is open in the sidebar drew a thin border around its pink row that the row's shadow partly covered. The open row has no menu border now (it is already marked); other rows keep it.
- After opening another space while the terminal panel was open, closing the last terminal left the canvas cut off at the height it had with the panel, with only the scenery below. The canvas now follows its area whenever the panel opens, closes or is resized (*Arrange nodes* also centers in the visible part while the panel is open).
- A header or sidebar button clicked with the mouse stayed highlighted until something else was clicked (for example the lock or *Arrange nodes*), so it looked pressed. The highlight now shows on hover and on keyboard focus only.
- Pressing the mouse on a node's image and dragging dragged a ghost of the image instead of the node. The image now lets the mouse through, so the node moves.
- Error dialogs and error notices lost the line breaks of their message ("…git-bash.exe Check "Git Bash path" in Settings." ran together), and the "Failed to start SSH" / "Failed to copy" dialogs did not close with Enter because the focus was not on OK. Line breaks are kept and OK has the focus.
- In an app window lower than the Settings dialog, the dialog was cut off at the top and at the bottom and nothing scrolled, so *Save* could not be reached with the mouse. The Settings, Info and From SSH config dialogs now stay inside the window: the title and the buttons are always there, and the part between them scrolls when it does not fit.
- The Settings and Info dialogs now act like dialogs for the keyboard: the focus moves into them when they open, Tab stays inside instead of wandering through the buttons hidden behind them, and closing returns the focus to the menu button. The Git Bash path field and the Close to tray switch are named by their labels for screen readers.
- A validation message in the node settings pushed every field below it down while typing, and the field showed Bootstrap's round warning icon and red glow. The field now only gets the theme's red border; the message floats just under it in a flat box while the field has the focus or the pointer, so nothing else moves.
- With many terminal tabs the active tab and the "Hide terminals" button were scrolled out of sight, so none of the visible tabs looked selected. Tabs now shrink first, the active tab is always scrolled into view, the hide button stays put, the mouse wheel scrolls the tabs, and a tab's tooltip names it. Space selects a tab, and closing a tab with the keyboard no longer selects it first and leaves the focus in the remaining terminal.
- In Vapor Blue, yellow text in the terminal was purple (the palette's sun color) and hard to tell from its magenta. Yellow and green in the terminal are now the same fixed yellow and green as the connection states, in every palette. In Sunset Drive the terminal's red and magenta (both pink) and yellow and cyan (both orange) looked alike; it now has its own violet magenta and cyan.
- With a long target host, the forward line under a node was cut before its count, so "(+5)" for the other forwards disappeared. The count now always shows; only the first forward is shortened.
- Pointing at a sidebar item made it 2px taller (its `...` button was taller than the name), so every item below jumped. The button now fits the row.
- Turning on *Node glass* moved the text under every node about 4px down (the panel's padding). The panel now grows outward around the text, so the text stays exactly where it is with the glass on or off.
- Sidebar items picked with Ctrl+click were only tinted, so neighbours merged into one block and the focused one looked different. Each now has a bar on its left and a thin gap to the next.
- The warning shown when you open another item while the editor is unlocked had a whole question as its title (two lines in the pixel font) and a short, unexplained body. It is now titled *Unsaved changes* and says that changes are saved only when the editor is locked again.
- Opening a node's *Port forwarding* or *Setting* popover with the keyboard left the focus on its button, so Tab went through the other node buttons first. The focus now moves into the popover (it was moved while the popover was still hidden).
- The sidebar search box showed no sign of having the keyboard focus; its border now lights up like other inputs.
- Connection lines ended about 2px above and left of the socket centers (Rete measures sockets without the node's border). The node frame is now drawn as an inset outline, so lines meet the sockets exactly.
- With the sidebar open, the "No space open" hint and the header title were partly hidden behind it; they now center in the visible part.
- Small inputs had three different heights (29/31/33px) depending on whether a button was attached, and the remove button of a forward row was taller than its inputs. They now share one height.
- In the settings, a label whose control has a help text below it sat halfway down next to the help text instead of next to the control. Labels now line up with the first line of their control, here and in the node settings.
- The column title "Local port" in the port forwarding popover broke onto two lines. *Delete* in a node's right-click menu used a fixed red instead of the palette's, and turned pink like the other items when pointed at; it now turns red.
- A user, host, key path or exec that the launch would reject was only reported when a connection started. The node settings now mark such a field while you type and say what is allowed (the same rules main checks).
- The red dot of a terminal tab that ended with an error could not be seen while the tab was active (the active tab is pink); the dot now has a dark border there.
- The fields in a node's settings were not tied to their labels: clicking a label now moves to its field, and screen readers announce the field's name.
- The hint toast (for example "Unlock the editor ...") was a light grey box with white text; toasts now use the theme colors, error toasts with a red header.
- A connection that failed in the app terminal (for example *Connection refused*) waited for Enter and looked like an open session: the tab stayed "running" and the path stayed lit. The session now ends right away; the tab shows the exit status and a red dot.
- The "previous image" button could not return to the first image.
- The generated script ignored a hang-up: after its window was closed it could still run its last lines. It now exits on HUP and TERM.
- A key path with a control character could pass validation after an earlier value had been rejected (shared global regex).
- ProxyJump failed with an error for a node whose key was never set, and wrote an empty `IdentityFile` line for one whose key was cleared. Temp files were written to the working directory and never cleaned up.
- Saved data contained a copy of the previous nodes (including their passwords) inside every node. It is no longer saved and is removed from existing files.
- Failed launches show the reason instead of a generic alert.
- Removing items asks for confirmation, and removing unselected items no longer closes the open editor.
- The port forwarding and settings popovers were pushed out of the window when their node was near the right edge, and never lined up with their icon.
- Sidebar: an empty list says how to add an item, and a search without results says so instead of showing nothing.
- Sidebar: the search ignores case, long names stay on one line (full name as tooltip), Escape cancels a rename instead of saving it later, and adding an item clears the search so it does not disappear.
- The window title follows the opened item. Before, a new item showed the name of another item, and renaming or removing the opened item left the old name.
- The node right click menu showed two "Delete" entries, one of which skipped the confirmation for nodes with content. There is one now, and it asks. While the editor is locked the right click menus (which did nothing) are replaced by a short hint to unlock the editor.
- An empty screen says what to do, the Info and Settings popups close with Escape, and the Info popup no longer credits the removed Vue CLI plugin.
- Importing a file that is not JSON, or not a jumpspace export, says so instead of showing an internal error.
- An empty "Git Bash path" in Settings means the default. Before, the screen showed the default but Connect failed with "Git Bash was not found".

### Removed

- The unused `upath`, PWA, comment/minimap plugin and `core-js` dependencies, the global Vue mixin and the unused footer placeholder.
- `vue-router`: the app has a single screen, which is now rendered directly.

### Notes for upgrading

- Password sign-in needs OpenSSH 8.4 or newer (`SSH_ASKPASS_REQUIRE`), which current Git for Windows includes.
- Spaces that use the older way to forward (an extra node that only holds the target host, with an empty port) keep working unchanged.
- Forwards saved by an older version on a node that has a user, host and port are moved automatically when the data is loaded: they go to the previous node with this node's host as the target, which opens the same tunnel as before. (The previous version of the file stays as `projects.json.bak`.) An entry is left on its node, now pointing to `localhost`, only when the previous node already uses the same local port or there is no previous node.
- Development needs Node.js 20.19+ or 22.12+.
