# jumpspace: notes for Claude

A visual SSH connection editor (Electron 44 + Vue 2.7 + Rete v1). Servers are nodes, chained nodes are jump hosts, one click runs the right `ssh` command in a terminal inside the app (Git's `bash.exe` on Windows) or in a Git Bash window. Windows + Git Bash is the target; development and CI also run on Linux.

The owner writes Korean: answer in Korean in chat, keep code, commit messages and docs in English. Code comments are mostly Korean; match the file you are editing.

## Rules that matter

- **Nothing user-controlled reaches a shell unchecked.** Every value that ends up in an `ssh` command or config goes through `src/shared/validate.js` (main checks before running; the node settings form shows the same rules while typing); `ssh.js` builds a bash script with POSIX single-quoted values. Passwords travel only as environment variables and are answered through `SSH_ASKPASS` (the generated script is its own askpass). Never put passwords or keys into logs, docs or commit messages.
- **The repository is public (MIT).** No secrets, tokens, real hosts or personal data in files or commit messages.
- **Behavior changes need a test.** After adding a test, break the code on purpose once and see it fail. Never skip or delete a failing test to get green.
- The renderer is sandboxed with a narrow IPC API (`src/preload/index.js`; `src/preload/ipc.test.js` reads the sources and fails when a channel of the preload has no receiver in main or the other way round, when main takes a request past its two sender-checking wrappers, or when the page calls something the preload does not offer). Keep logic that can be pure in `src/renderer/src/utils/` or `src/main/*.js` with tests; components stay thin. Values both processes need (setting defaults and validation, the canvas zoom range) live once in `src/shared/` (no Node modules there).
- **Keep the docs true.** A user-visible change goes into the Unreleased section of `CHANGELOG.md`; a new file in `src/main` or a new node component goes into the "project layout" of `README.md`.
- Saved data (`projects.json`, items are `{ name, data, view? }`) goes through `normalizeItems` in `src/main/storage.js`. Saves are queued there (one at a time, in the order asked for; a failed one does not stop the next): the renderer saves from several places (`saveProject()` in `Layout.vue`: on locking, on a change of the diagram list, 0.4 s after the canvas moved) without waiting for each other, and overlapping saves shared `projects.json.tmp`, so the later `rename` failed with ENOENT (seen by the owner, 2026-10-11). The `rename` onto `projects.json` is tried again after EPERM, EBUSY or EACCES (6 waits, about 1.5 s in all): Windows refuses it while anything has the file open, which a test that read the file right after a save ran into once. `createProjectStorage(dir, { renameFile, wait })` takes both for the tests. Old data must keep loading; add a migration there instead of breaking it. While a save has not ended a faint ring turns in the header (owner, 2026-10-11; the word *Saving* that stood there first flashed with every save and bothered the owner): `savingCount` in `Layout.vue` goes up before `saveProjects` and down in `finally`. The place of the mark (`.save-state`, first in the toolbar slot, 1rem square) is always there, so the buttons do not move; the `b-spinner` in it has the `v-if`.

## Gotchas learned the hard way

- The popovers (v-tooltip / popper.js 1.x) are moved out of the window by the `arrow` modifier because the arrow element has no styles; it is disabled in `main.js`. Keep it that way.
- Styles of `rete-context-menu-plugin` are scoped (`.item[data-v-x]`); overriding needs a more specific selector such as `div.context-menu div.item`.
- Rete plugins need `regenerator-runtime` (imported first in `main.js`).
- The look (colors, fonts, Bootstrap overrides for buttons, forms, dropdowns, modals, toasts) lives in `src/renderer/src/assets/theme.scss` as CSS variables; components use `var(--js-*)`. No logos or other brands' artwork, only the general style. **Nothing is animated** (owner, 2026-10-11: "just turn all the animations off", after the canvas looked as if it was not being updated in the real window; the cause was not looked for). Our styles and components have no `animation`, `@keyframes`, `transition` (other than `none`), Vue `<transition>`, drag animation of the tab row (`:animation` of vuedraggable) or blinking terminal cursor, and `src/renderer/src/motion.test.js` fails when one comes back; a change of state or a hover shows at once. Bootstrap's own transitions (its dialogs, toasts and buttons) are not touched. **One exception, the owner's own (same day, later: "how about just a faint, hardly visible rotating spinner"):** the saving mark in the header is a `b-spinner`, which turns by Bootstrap's own keyframes, so the sweep of our styles does not see it; `motion.test.js` counts the spinners instead and fails on a second one. It is in the page only while a save runs (`v-if`), so nothing turns the rest of the time. If the canvas looks as if it is not updated again, this is the first thing to take out. Gone with the animations: the signal that ran along the path of a session (a second `path.flow-path` on every connection), the blinking of the dots on the nodes, the pop of the right-click menu, the rolling band of the CRT background, the fades of the node menu and the popovers. So the states of a path must be told apart standing still (`components/editor/canvas.test.js` checks it with the values of every palette): `markLiveRoutes()` matches terminal sessions (their `hops`, `user@host:port` in path order) against the nodes with `routeStates()` from `utils/terminal-sessions.js` and sets one of `is-connecting` (line and arrow yellow, `--js-connecting`, yellow dot), `is-live` (connected: line in the main color, arrow `--js-signal`, green dot `--js-live`) or `is-failed` (red dashed, `--js-danger`, red dot; the only dashed line, because the red is close to the main pink) on the Rete node and connection views. A line with a session is 4px wide, an idle one 3px. The yellow and the green are the same in every palette on purpose (`--js-sun` is purple in Vapor Blue). It also puts `is-active-terminal` on the node the selected tab was opened from (`activeTerminalNode()`: the last hop of that session, nothing while the panel is minimized): its rule (`.is-active-terminal .node.site` in `canvas.scss`) must stay after the node's `:hover` rule, which changes only colors (owner, 2026-10-11: "change the color instead of moving"; frame `--js-sun`, background `--js-surface-2`, no transform, no other shadow). A node that was clicked while editing (Rete's `.selected`) has no look at all (owner, 2026-10-11: "selecting it does nothing anyway"); Rete still selects it, and `canvas.test.js` fails when a `.selected` rule comes back. This is a look, not a Rete selection (`editor.selected` is untouched, so drag and the node menu act on what the user selected), and the class sits on the view's wrapper element while Rete's own `selected` sits on the `.node` inside it. Locking the editor clears Rete's selection (`clearSelection()` on the `readonly` event), so in a locked diagram that look can only be the tab's node; the render plugin redraws the `selected` class only on `nodeselected`, so the cleared nodes are updated by hand. Selecting another tab changes no session, so the deep watcher on `terminalSessions` does not fire; `index.vue` watches the computed `activeTerminalNode` as well. While the diagram is locked a press on a node belongs to the canvas (`utils/locked-press.js`): Rete's node view stops every `pointerdown` on a node before the readonly plugin can refuse the drag, so a drag that started on a node did nothing. `index.vue` listens on `#rete` in the capture phase, stops the press there and dispatches a copy of it on `#rete` itself, where Rete's own canvas drag picks it up; buttons (`PRESS_KEEPERS`) are left alone. Do not do this with `pointer-events: none` on the node: the buttons appear on `.component:hover` and the details have `title` tooltips, both need the mouse on the node. "Connected" comes from an OSC marker (`src/shared/terminal-marker.js`) that ssh prints through `LocalCommand` after login, only in the app terminal and only as a command-line option (a `LocalCommand` in the `-F` config would also run in the ProxyJump `-W` helpers and corrupt the tunnel); the panel reads it with `term.parser.registerOscHandler`. A session ending with 255 counts as failed; other exit codes are the shell's and clear the path.
- Rete v1 places connection ends with `offsetLeft/offsetTop` sums, which skip the borders of parent elements. The node frame is therefore an inset `outline` plus `padding`, not a `border` (`components/editor/canvas.scss`, the canvas look: node box, sockets, connection states); a border on `.node.site` or the socket containers shifts every line off the socket centers.
- Rete v1 fixes the canvas container to pixel sizes (`view.resize()`), only on load and on window resize. The editor component calls it from a `ResizeObserver` on `#editor-area`, because the terminal panel changes the canvas height without a window resize.
- The diagram scales with the canvas area (owner, 2026-10). The editor remembers the view the user chose together with the area size (`base`); the `ResizeObserver` shows `shownView(base, area, full)` (`utils/view.js`) and never changes `base`, so every size change is undone exactly. `scaleView` zooms by the ratio of the **heights** and keeps the center centered. It must stay a rule that is its own inverse (A to B times B to A is 1): the first rule took the smaller of the two side ratios, which does not zoom in when only the height grows, so a view chosen while the terminal panel was open stayed small when the panel closed (owner, 2026-10-11: "it does not come back in the same ratio"). The price: a change of the width alone does not scale. Views the app itself chooses are made for the canvas without the panel (`fullSize()`: `#workspace`, the element the area shares with the panel) and shown reduced, because what fits the low and wide area gets cut at the sides when the panel closes: `resetView()` remembers `DEFAULT_VIEW` without a size (see below), and `arrangeNodes()` fits into `fullCanvasIn(area, full)`. A view without a size (a diagram that was never moved, an old file, one chosen while the area is collapsed) counts as a view of the canvas without the panel, whatever its size is at the moment; `openView` must not take the area of that moment for it (the header is a few px higher before a diagram is open, and the panel of the diagram may be open). `resetView()` must not give the starting view a size either: remembered with the size of the canvas at the press, it followed later changes of the window height like a view the user chose, so the screen after such a change was not what Reset view gives in that window, and the next press moved the diagram by a few percent and some px sideways (owner, 2026-10-11: "with the terminal on, when I change the height of the program, Reset view is subtly off"). So the starting view is the one view that does not follow the window: a reset diagram and one that was never moved are the same thing, the same in every window, and only the panel reduces it. A view without a size depends on the size of `#workspace`, so the `ResizeObserver` watches that element as well as the area: where the panel has pushed the canvas to its minimum height, a change of the window height changes `#workspace` and not the area. (A guard that only the wiring test in `view.test.js` holds: today the panel adjusts its height one step after `#workspace` changed, which moves the area for a moment, so the area alone also ends at the right view.) Changes made while rescaling (`isRescaling`) are not the user's: they are neither remembered nor emitted as `view-change`. The saved view carries the size as `w`, `h` (`sanitizeView` in `src/shared/view.js`; old files have none and open as before). The header must keep one height while a diagram is open, or the canvas without the panel has two sizes (a *Show terminals* button with a count badge, 1.2px higher than the others, once did that; the header has no terminal button since 2026-10-12, `views/header-tools.test.js`). It has the same height before a diagram is open: the name of the app in the title (`.header-brand`) has a line height that keeps it no higher than the name tag; with the default one the header was 5.8px higher and everything under it moved up when the first diagram opened.
- Connecting nodes is click, click only (owner, #95): the editor vetoes `connectionpick` while a `pointerup` is being dispatched (a window capture listener sets `isReleasing` until the next task), so `rete-connection-plugin` cannot pick a socket on release. Picks on `pointerdown` (start, target, picking up a line) are untouched.
- Measuring a node: its view element is only the box. The text under it (`.info-field`, absolute) and the sockets stick out, and the hover menu sits about 39px above it. `extentOf` in `components/editor/index.vue` adds the first two; the menu fits in `ARRANGE_GAP.y` (`utils/arrange.js`).
- There is no sidebar (owner, 2026-10: any side menu covers the canvas or the terminals; no VS Code layout). The diagram list (`components/layout/main-navigator.vue`) lives in `#diagram-switcher` in `views/Layout.vue`, a panel that hangs under the header title (`#diagram-switcher-toggle` in `main-header.vue`) and closes on a pick, Escape or a click outside (a transparent fixed backdrop). It is hidden with `v-show`, never unmounted: the navigator holds the item state.
- Terminals belong to the diagram that opened them (owner, 2026-10). The owner of a session is the navigator item's `index` (a runtime number, not saved); `views/Layout.vue` commits `terminalOwner` when an item opens or closes. The store getter `terminalSessions` is the open diagram's sessions (tab row, canvas paths), `allTerminalSessions` is everything (the panel keeps every xterm screen mounted, the list counts tabs per item with `countByOwner`). The active tab, the minimized panel, the maximized panel and the split are remembered per owner in the store.
- The terminal panel can be maximized (owner, 2026-10-11): it goes up to the header and takes the place of the canvas. The state is `isPanelMaximized` in the terminal store; the getter `isTerminalPanelMaximized` is true only while the panel is shown (a minimized panel shows the canvas and comes back maximized), and the last tab of the open diagram ends it. The panel then has no height style (`.is-maximized`, `flex: 1`), `views/Layout.vue` collapses the canvas (`#workspace.terminal-maximized > #editor-area`: `flex: 0 0 0px` and `visibility: hidden`, so the hidden node buttons take no focus) and leaves the diagram buttons (eye, lock, reset view, arrange) out of the header, which have nothing to act on meanwhile. Lowering is the tab row's button only: a second *Lower terminals* button in the header was dropped by the owner as a duplicate. Never hide the canvas with `display: none`: Rete measures the sockets with offsets, which are 0 there, so a diagram opened meanwhile gets its lines drawn from the node corners (`views/canvas-collapse.test.js`). While the area has no height the editor shows the remembered view unscaled (`scaleView` ignores a size of 0), and the next real size brings the scaled view back. A view opened during that time without a saved size (picking another diagram calls `openView` before Vue has redrawn, so the area is still collapsed) is remembered without one and counts as a view of the canvas without the panel (`shownView` in `utils/view.js`), so it is reduced like every view once the panel is lowered. Dragging the top edge goes through `panelDrag` in `utils/terminal-view.js`: the panel stops at the limit of `panelHeight` and snaps to maximized `MAXIMIZE_SNAP` px further up; the same rule lets go when the edge is dragged down. A drag that ends maximized keeps the height chosen before it, so lowering does not leave the canvas a strip.
- Small controls share one height (`$control-sm-height` in `theme.scss`); Bootstrap computes it from the font size, which differs between a plain input and one with an attached button.
- Icons are registered one by one in `assets/icons/index.js`; an unregistered `b-icon` renders an empty button. `assets/icons/icons.test.js` fails when a component uses one that is missing.
- The terminal panel can be split left and right (owner, 2026-10-12: "left and right is enough"). One tab row, two tabs in sight: `activeKey` (the selected tab, it has the keyboard) and `sideKey` (the tab of the other half, null = not split), with `activeSide` saying which half the selected tab is in; all three live in the terminal store and are remembered per diagram. The rules are pure functions in `utils/terminal-sessions.js`: `shownPanes` (which tab is in which half), `activatePane` (the tab of the other half: move there; any other tab: replace the tab of this half), `closePane` (closing one of the two tabs ends the split and the other one stays) and `splitPartner` (the next tab, else the one before). `terminal-panel.vue` shows both screens (`.is-left`, `.is-right`, 50% each, no draggable divider), fits both in `fitActive`, and selects a half when its terminal gets the focus (`@focusin`); a half changes its number of columns, so both sessions are resized when the split starts and ends. Not built on purpose: a top/bottom split, more than two halves, a tab row per half.
- A minimized terminal panel is its tab row at the bottom of the window (owner, 2026-10-12: "going up to the header and getting small there feels odd"). `isPanelOpen` false no longer hides the panel: `terminal-panel.vue` stays as long as the open diagram has sessions, gets `.is-minimized`, no height style, and hides `.terminal-body` and the resize edge; `terminal-tabs.vue` (`isMinimized`) marks no tab as selected and turns the dash into *Show terminals* (event `show`). A tab click opens it through `terminalActivate`, the maximize button through `maximize()` of the panel. The canvas has everything above the row, so the diagram is reduced by those 40px like by every panel height; only a diagram without terminals has the full canvas. The canvas marks no node while it is minimized (`activeTerminalNode`).
- Terminal tabs with the same name get a number (owner, 2026-10-12): `duplicateNumbers` in `utils/terminal-sessions.js` works it out from the tabs of the open diagram when they are drawn (by the order they were opened, nothing is stored in the session), and the tab row shows it in its own `.terminal-tab-number` after the name, which never shrinks, so the number survives the ellipsis of the name.

Its list is a `vuedraggable` (tabs are dragged to reorder; `reorderSessions` in `utils/terminal-sessions.js` moves only the open diagram's sessions inside the store's list, so `$refs.tabList` is a component and the element is `$refs.tabList.$el`). The list (`.terminal-tab-list`) hides its scrollbar on purpose: a classic scrollbar takes height from the tabs and moves their text. Tabs shrink to a min-width first, the wheel scrolls the list and `revealScrollLeft` keeps the active tab in view (on a tab change and through the row's own ResizeObserver); the panel's three buttons sit outside the list, at the right end of the row: split (not there while minimized), maximize (it becomes *Lower terminals* while maximized) and minimize (the dash; it leaves only this row at the bottom of the window and becomes *Show terminals*).

A password of only spaces is a value (it is saved untrimmed). With nothing to show, one line says that nothing is filled in; *Copy SSH config* stays in every case.
- The lock button is the last of the diagram buttons in the header (the `#main-navigator-toolbar` slot in `Layout.vue`), so it is the left neighbor of the gear in every state and does not move when it is pressed (owner, 2026-10-11: "it is important, keep it always left of the setting button"). A new header button goes to its left; `views/header-tools.test.js` reads the order and the `v-if` of each button from the template. It is away with the other diagram buttons while the terminal panel is maximized or no diagram is open. Reset view is its left neighbor and is there locked or not (it changes only the view); Arrange nodes shows left of that while unlocked. Reset view is one function, `resetView()` of the editor component (it remembers `DEFAULT_VIEW` without a size, which makes it the view of the canvas without the terminal panel in a window of every size, and shows it for the area of now, see the scaling above): the header button and the double click on the canvas both call it (owner, 2026-10-11: "make the double click do the same as Reset view"), and Rete's own zoom on a double click stays vetoed. - *From SSH config*, the second item of the canvas menu (owner, 2026-10-11: "paste an SSH config there and it creates a node that holds only what is in it; the other values are the defaults or stay empty"). `parseSshConfig()` in `src/shared/ssh-config-parse.js` is the reverse of `buildSshConfig()`, and its first tests are the round trip; a keyword a node has no place for is reported (`ignored`), never guessed. `importPlan()` in `utils/config-import.js` turns the hosts into node values, links and the rows the dialog shows. - Hiding node details (the eye button, setting `hideNodeInfo`) masks instead of removing (owner, 2026-10): `maskText` in `utils/mask.js` turns user, host, port and the forward summary under a node into `***` (each dotted part on its own: `***.***.***.***`), also in their tooltips. Names stay.
- Reconnecting a terminal tab: main (`terminal.js`) keeps the request of a session that ended by itself until its tab is closed (`close` also forgets ended ids, `closeAll` clears them, at most `2 x maxSessions`); the renderer only asks `terminal:reopen` with the old id. Never put the request back into the store. A tab the user ended (`endedByUser` in `utils/terminal-sessions.js`: logged in and any exit code but 255, 130 from Ctrl+C while connecting, or 255 within 3 s of a Ctrl+C typed in that tab, which is how `ssh -N` ends) closes by itself; only failures stay for reconnecting. main reports a pty killed by a signal as `128 + signal` (`exitStatus`).
- `b-form-input` with `trim` is fine for typing spaces; do not "fix" it.
- The Windows CI runner checks files out with CRLF line ends. A test that reads a source file (`theme.test.js`, `icons.test.js`, `image-drag.test.js`) must not search for `'\n'` without normalizing `\r\n` first.
- On Windows Git Bash puts its own `/usr/bin` before `PATH`, so tests that fake `ssh` must use a bash function (`BASH_ENV`), not a fake binary on `PATH`.
- The Settings, Info and From SSH config popups are `b-overlay` cards, not `b-modal`: the `dismissOnEscape` mixin (`utils/dismiss.js`) gives them Escape, the first focus, a Tab trap and the focus return. A new popup of that kind needs `ref="dialog"` (plus `role="dialog"`, `aria-modal`, `aria-label`) on its card (`components/layout/popup/config-popup.test.js` reads every popup in that folder for it). The first focus waits a frame because b-dropdown puts the focus back on its toggle after a menu item click. Such a card stays inside the app window (`.card[role='dialog']` in `theme.scss`: `max-height` of the window less a margin, and only its `.card-body` scrolls, so the title and the button row are always there): Settings is 680 px high and the content of the default window 729, and in a lower window the card was cut off at both ends with nothing to scroll, so *Save* could not be reached with the mouse. The band on top (`::before`) needs `flex: none` there, or it shrinks with the body. Playwright's headless browser hides scrollbars (`--hide-scrollbars`); take that default argument out to see the scrollbar.
- Diagram list items are positioned (for the highlight), so an item whose `...` menu is open needs a higher `z-index` or the menu hides behind the next items.
- Vue 2 reactivity: a property added later to an item needs `$set`; navigator items and `projectData` in `views/Layout.vue` are separate copies that are rebuilt on every `updated` event.
- Terminals in the app: `node-pty` is the only runtime `dependencies` entry (native, N-API, prebuilt for Windows/macOS, compiled with node-gyp on Linux), so electron-vite keeps it external and electron-builder packs it (`npmRebuild: false`, `asarUnpack`). `pty.kill()` only signals bash; `killPty` hangs up the whole process group so ssh ends too.
- The app terminal is drawn by `@xterm/addon-webgl` (owner, 2026-10-11: "with Claude Code there are gaps between the lines"). The default DOM renderer of xterm.js takes box and block characters from the font, and they break between rows and cells at fractional sizes; only the WebGL renderer draws them itself (`customGlyphs`; xterm.js 6 has no canvas renderer any more). `drawWithWebgl()` in `terminal-panel.vue` loads it after `term.open()` and disposes it on a lost context, which brings the DOM renderer back: a browser keeps about 16 WebGL contexts, and every tab of every diagram stays mounted. There are no `.xterm-rows` elements any more (a headless check that counted them reads `term.rows` now). In a headless browser with an emulated `deviceScaleFactor` the WebGL canvas comes out magnified; that is the emulation (the canvas is sized from `devicePixelContentBoxSize`), use `--force-device-scale-factor` to look at another scale.
- The pty on Windows (owner, 2026-10-11: "tmux, Claude Code and Codex do not behave correctly, the cursor flashes where the screen moves"). `terminal.js` starts sessions with `useConptyDll: true`, the ConPTY that node-pty ships (`prebuilds/win32-*/conpty/`: `conpty.dll` + `OpenConsole.exe`, Windows Terminal 1.23), and falls back to the one in Windows for good when that spawn throws. Measured on Windows 10 (19045): the built-in ConPTY draws the program's output into its own screen and re-emits it, so mouse requests (`?1000h`), the alternate screen (`?1049h`), hyperlinks and curly underlines never reach xterm.js, passed-through sequences arrive out of order, and at the start of every redraw the cursor is shown where the redraw begins (its "hide cursor" is a broken `ESC[25l`); the bundled one hands everything on in order. It asks the terminal `ESC[c` at start and waits up to 3 s for the answer (xterm.js answers through `term.onData`; a test without a screen must answer itself). xterm.js must be told about the pty (`windowsPtyInfo` in `terminal.js`, sent with the result of `terminal:open` / `terminal:reopen`, set as `term.options.windowsPty` before the first output): without it, more rows pull scrollback into view, ConPTY repaints those rows as blank and the lines are lost; with the bundled ConPTY the build number must be at least `REFLOW_BUILD` (21376), or xterm.js leaves long lines cut off after a resize.
- Terminal font size (`terminalFontSize`, 8 to 32, a setting without a row in the Settings window): `terminalShortcut` matches the **character** (`+`, `=`, `-`, `0`), never `code`, because Ctrl+Shift+- has the character `_` and must reach the program as `^_`. The panel applies the size in `fit()` only, so a hidden screen gets it when it is shown (xterm.js may not be able to measure a hidden one). The keys go through the store action `settingChange` (shown at once, written `SAVE_DELAY_MS` after the last change); the Settings window keeps `settingSave`.
- Leaving with the editor unlocked: the page only **holds** the unload (`holdUnload` in `views/Layout.vue`, `beforeunload` with `returnValue`), main asks in `will-prevent-unload` with a system dialog (`src/main/unload-question.js`) and calls `preventDefault()` there to let the close, reload or quit go on. No IPC and no state for it. The window's `close` event comes before `beforeunload`, so hiding to the tray never asks. A cancelled quit must reset `isQuitting`, and terminals end in `will-quit`, not `before-quit` (that one comes before the question). If the dialog throws, the window closes.
- The window bounds live under their own electron-store key `window` (`src/main/window-bounds.js`), **not in the setting**: the renderer reads and writes the setting as a whole and would write old bounds back. `restoreBounds` decides what is usable; main saves `getNormalBounds()` (a maximized window's `getBounds()` is the screen). On a scaled screen Electron rounds outwards every time bounds go to physical pixels and back, so a window opened with what it had reported grew with every start (seen in the real window at 125 %, 2026-10-12: 900 wide became 931 in five starts). `restoreBounds` therefore gets the `scaleFactor` of each screen and moves the four values to the nearest multiple of `pixelStep` (4 at 125 % and 175 %, 2 at 150 %), which round-trips exactly, and `createWindow` calls `setBounds` once more after the constructor, which alone makes a placed window a few px larger than asked. Do not "simplify" either away; neither can be seen at 100 %.
- The terminal font is loaded by hand (`loadFonts` in the panel, both weights, at mount): a `@font-face` file is fetched on first use, and the WebGL renderer of xterm.js keeps the glyphs it drew with the fallback font in its atlas. No DOM text uses the bold weight, so without this the first bold output is drawn in two fonts. A new weight or font needs a line there.
- Find in the terminal (`terminal-search.vue`, Ctrl+Shift+F only: Ctrl+F is `^F` for the program): `@xterm/addon-search` **without decorations** (they need `allowProposedApi`), so a match is the terminal's selection and "No match" is the return value of `findPrevious`/`findNext`. One field in the panel for the selected tab; it closes when another tab is selected (watcher `activeKey`), so the focus rules of `shownKeys` stay as they are.
- The keys of the terminal are listed in the Info window from `TERMINAL_KEYS` (`utils/terminal-keys.js`); `terminal-keys.test.js` presses each listed key through `terminalShortcut` and fails when a shortcut has no row, so a new or changed key needs its row there. The Info window must fit the default window without scrolling (the icon is 96 px and the texts are one line each for that; `info-check` of the headless checks measures it in every palette).
- Terminal output is batched in main (`OUTPUT_DELAY_MS`, 8 ms from the first piece, sent before the exit, dropped when the tab is closed, at once above `MAX_PENDING_OUTPUT`): the bundled ConPTY delivers one redraw of Claude Code or tmux in about 25 pieces, and xterm.js painted between them (half a redraw with the cursor in it). 4 ms was not enough. A test with the fake pty must advance fake timers or end the session to see output. The cursor is the text color on the background color (`terminalTheme`), not a palette color. A right click belongs to the program while `term.modes.mouseTrackingMode` is not `none` (`rightClickAction` in `utils/terminal-sessions.js`; Shift gives it back to the terminal). `exitStatus` reads the signal out of the exit code of Git's bash on Windows (`signal << 8`: Ctrl+C while connecting ends with 512, reported as 130). `resize` and `write` swallow the pty's errors: node-pty throws "Cannot resize a pty that has already exited" between the end of the program and its `onExit`.
- **Git's ssh loses window size changes on Windows and can die on the next key** (measured 2026-10-11, Git for Windows 2.55, OpenSSH 10.5p1, MSYS runtime 3.6.10, Windows 10; details under Known bugs in `LOOP_LOG.md`). After a pty resize ssh sends no `window-change` in 1 to 6 of 10 cases, with both ConPTYs, with or without `exec`; the key after such a resize is sometimes swallowed, and in about one of six cases ssh exits 255 with `poll: No error`. Nothing the app sends helps: an explicit `kill -WINCH` is not acted on in that state (and makes the next key more dangerous), a focus report loses its first byte, waiting up to 4 s before the key changes nothing. Windows' own `System32\OpenSSH\ssh.exe` (9.5p1) passed every resize in the same test. Do not rebuild a signal or "nudge" workaround. The owner decided on 2026-10-11 to leave it as it is ("a person who sees it can call a redraw once"): no switch to Windows' ssh, no workaround in the app; README says what a person can do (change the size once more; a redraw key is a key like any other in that state).
- The base font is Pretendard (owner, 2026-10; the variable woff2 with its OFL text in `assets/fonts/Pretendard`, declared in `App.vue`, Spoqa Han Sans Neo as the fallback; `--js-font-base`). It is set on `body` (plus `.tooltip`, `.popover`) in `theme.scss`, which must stay after Bootstrap in `main.js` (Bootstrap sets a font on the same selectors and won while the rule lived in `App.vue`), and inherited. Never put it on `*`: that overrides every class that sets `--js-font-display` on a parent (the text inside a button stays in the base font) and breaks xterm's character grid.
- The pixel font is VT323 under the name `JS Pixel` with `size-adjust: 128%` (`theme.scss`), because VT323 is much smaller than other fonts at the same size. Sizes of display text are chosen for that.
- The picture at the top of the README is `docs/screenshot.png` (1200 x 760, not packed into the installer). It is taken on the headless screen with a made-up diagram, by `readme-shot.cjs` of the checks that are not in the repository; take it again when the look changes, and never from a real diagram.
- Palettes are `:root[data-theme=...]` blocks in `theme.scss`; a new one also needs its name in `THEMES` (`src/shared/setting.js`) and a button in the settings popup (`components/layout/popup/setting-popup.test.js` compares the buttons of the Theme, Background and Terminal colors rows with their lists, and fails when a setting with a row is not read in `init()` or not sent in `saveSetting()`). Every hard shadow (`--js-drop` and the `Npx Npx 0` shadows in the components) has the palette's `--js-shadow`, never black: black cannot be told apart from the dark backgrounds, so neither the shadow nor the edge of the panel on it could be seen. It is lighter than `--js-surface-2` and darker than `--js-line` (70 % of the way from `--js-bg` to `--js-line`); `theme.test.js` checks its contrast in every palette and that no `box-shadow` in the styles is black. The terminal takes its colors from the palette (`terminalTheme` in `utils/terminal-view.js`): yellow and green are the fixed `--js-connecting` / `--js-live`, magenta and cyan are `--js-ansi-magenta` / `--js-ansi-cyan` (the primary and secondary unless a palette sets them, as Sunset Drive does); `terminal-view.test.js` reads the real palettes and fails when two of the six ANSI colors are less than 15 degrees of hue apart. The setting `terminalColors` (`TERMINAL_COLORS` in `setting.js`: `vivid`, `soft`, `muted`; *Settings > Terminal colors*) says how far those six are toned down (owner, 2026-10-11: the terminal was "too glaring", then "can I pick one of the three in the settings"; the neon colors suit dots and lines, not the whole green status line of tmux). The toned colors are **computed**, not written into `theme.scss`: `terminalTheme(color, level)` cuts lightness and chroma in OKLCH at the level's limit and keeps the hue (`tone()` in `utils/color.js`), so a change of a palette color carries over and the variables the canvas uses (`--js-live`, `--js-connecting`) are never retuned for the terminal. `vivid` is exactly the theme from before the setting: the palette colors, and no `black` and no bright colors set, so bold text uses xterm's own bright table. In `soft` and `muted` the bright colors are the same hues a little lighter and more colorful (never the neon color itself, or bold text is more glaring than before), `black` is the palette background (black text on a colored bar), and yellow has a floor (a dark, dull yellow is olive). The default is `soft`, also for a setting file without the key. `terminal-panel.vue` builds the theme in `colors()` and sets it again on every open terminal when the palette or the level changes (the computed `colorSetting`); `terminal-view.test.js` checks every palette at every level (hue kept, never stronger than the palette color, calmer level by level, contrast 4.5 on the background) and pins the colors of Sunset Drive, the ones the owner chose from. The background scene (sky, sun, city, grid) is plain CSS in `components/layout/scene-backdrop.vue`: `.scene-art` holds the picture, `.scene-fx` the overlays, and the setting `backdrop` (`BACKDROPS` in `setting.js`) picks a `.scene-<name>` class (and `#editor-area.backdrop-<name>` in `views/Layout.vue`; Vivid uses it to give lines a dark `drop-shadow`). The setting `nodeBlur` (0..`NODE_BLUR_MAX` px, 0 = off) adds `.node-glass` and `--node-blur` to `#editor-area`: the text under a node (`.info-card`, as wide as the text) becomes a frosted panel with a `backdrop-filter`; the node box itself is left alone (a panel around it also blurred the connections, which are drawn below the nodes). Dim the scene with opacity, not `brightness()`, and warm the sun in dimmed modes: a darkened yellow turns olive.
